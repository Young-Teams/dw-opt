# 代码审查

独立代码审查默认使用当前会话中可见的 subagent 线程，角色定义在 [.codex/agents/code_reviewer.toml](../.codex/agents/code_reviewer.toml)。用户可以查看审查者的进展、工具调用和结果；主 Agent 汇总发现并处理修复。实验结论仍由人通过对应 `task.md` 审阅。

## 触发条件与范围

| 修改 | 处理方式 |
|---|---|
| 文档、小型辅助修改、尚在探索的独立候选 | 相关自检；需要时再独立审查 |
| 新增或修改准备共享使用的算子、公共接口、框架或实验调度逻辑 | 相关验证后进行独立代码审查 |
| 公共参考模型、测试断言、共享综合约束、指标解析等评测逻辑 | 独立代码审查，说明可能影响哪些已有结果 |
| 仅将已有代码纳入 Git，未改执行逻辑 | 核对入库范围、内容一致性、依赖与入口；需要全面审查既有实现时单独明确范围 |

单次实验的参数选择和结果解释记录到 `task.md`，不自动触发代码审查。审查范围以约定目标和实际修改为准，不因提交中存在大量新文件就自动扩大为全仓库或全部历史实现审计。

## 启动与上下文

主 Agent 使用 subagent 工具启动 `code_reviewer`，不通过终端再启动隐藏输出的 CLI 审查进程。先固定候选提交，记录基准与候选 SHA；审查期间保持对应内容稳定，需要并行修改时使用独立 worktree。

- 显式关闭主会话历史继承。当前 `spawn_agent` 工具使用 `fork_turns="none"`；其他客户端使用其实际提供的等效选项，不假设默认隔离。
- `fork_turns` 是当前编排工具的调用参数，不写入 Agent TOML。角色文件中的“不要读取历史”不能清除已经继承的上下文。
- 委派消息只提供目标、验收、版本、文件范围、必要接口约束和验证证据，不传完整实现对话。缺失必要输入时，审查者向主 Agent 询问。
- 支持按角色名选择的客户端使用 `code_reviewer`。当前工具没有角色选择参数时，让子代理显式读取该 TOML 的 `developer_instructions`，并如实说明没有验证配置的自动加载。
- TOML 设置只读默认值；实际权限仍受客户端和父会话的运行时策略影响。审查者在任何模式下都不得修改被审查文件。

委派消息示例（替换实际版本、范围和证据）：

```text
按 .codex/agents/code_reviewer.toml 的角色指令进行独立审查。
目标：<具体问题与预期行为>。
验收：<可核对条件>。
版本：<基准 SHA>..<候选 SHA>。
范围：<明确文件列表和必要接口约束>。
证据：<已执行检查的命令、结果或现有日志路径>。
只读检查；先在线程中说明范围，发现问题时给出位置及依据。
完成后报告已检查范围、按影响排序的发现和未验证项。
```

## 可见过程与结果

审查者在自己的线程中报告范围、重要进展和最终结果。主 Agent 在主会话记录线程标识、被审查版本和结论；修复后通过同一线程发起仅针对受影响部分的复核，并提供修复提交。

简单审查直接保留会话记录，无需新建 `tasks/` 或 `experiments/` 目录。已有任务时在 `task.md` 记录版本、线程、发现及处理。需要单独归档日志时按任务约定执行，不默认建立整套 Run 目录。

- 优先检查参考模型、测试、约束和指标处理，再检查实现与调用者影响。
- 发现须附文件位置、影响及证据或复现方法；未确认的问题标为待核验，不凑问题数量。
- 审查者不修改实现、不放宽验收、不判断实验结论是否被采纳。
- 主 Agent 记录修复提交或暂缓、不采纳的理由；修复后复核受影响部分。
- 不默认套用固定的四分钟终止时间。需要时间或资源上限时，在委派任务中明确；超时、阻塞或中断记为“未完成”，不能标记为通过。

## 内置审查入口

`codex review` 是非交互式代码审查命令，可针对未提交修改、基准分支、单个提交或自定义审查指令执行。它不等于自动运行完整测试或形式验证，也不要求创建本仓库的实验目录。

交互式 CLI 的 `/review` 会把结果写入会话记录；App 和 IDE 也提供会话内审查入口。需要这些内置功能时可以直接使用，但不能假设它们满足本仓库独立审查的历史隔离要求。独立审查默认仍按上述 subagent 流程执行。

手动使用非交互式 CLI 时，`--uncommitted`、`--base`、`--commit` 和自定义 prompt 只能选一种；不要把未提交的无关文件一起纳入。该入口不作为主 Agent 日常独立审查的默认方式。
