# 代码审查

代码审查使用 Codex 内置 reviewer。实验结果与科研结论由人通过对应 `task.md` 审阅，不自动安排实验结论审查 Agent。

## 触发条件

| 修改 | 处理方式 |
|---|---|
| 文档、小型辅助修改、尚在探索的独立候选 | 执行与改动相关的自检；需要时再审查 |
| 准备作为共享实现使用的算子、公共接口、框架或实验调度代码 | 相关验证后进行独立代码审查 |
| 公共参考模型、测试断言、共享综合约束、指标解析或其他共享评测逻辑 | 独立代码审查，并向人说明可能影响哪些已有结果 |

变更很小时可直接在对话记录审查范围和结果；已有任务目录时，记录到 `tasks/<任务名>/task.md`。代码审查通过不替代人工对实验结论的判断。

单次实验的参数选择、约束扫描和结果解释记录到 `task.md`，由人审阅。只有同时修改共享实现或评测逻辑时，才对相应代码触发上述审查。

## 上下文与版本

单独启动审查任务，不续用实现过程的对话，也不附带完整实现聊天记录。提供目标、验收标准、代码范围、必要的接口约束和验证证据。审查者可以读取项目规则和相关源码。

正式审查固定候选提交，并记录基准与候选 SHA；审查期间保持对应工作区内容稳定。需与开发并行时，使用独立 worktree。审查结论只对应记录的代码版本。

从仓库根目录单独调用，例如：

```bash
# 快速检查尚未提交的改动
codex review --uncommitted

# 固定当前提交后进行审查
review_commit=$(git rev-parse HEAD)
codex review --commit "$review_commit"
```

以上为两种入口，按需要选择。一个任务跨多个提交时，使用明确的基准与候选范围，例如以下自定义 prompt 模板（替换其中占位内容）：

```text
审查 <基准SHA>..<候选SHA> 的代码变更。读取 tasks/<任务名>/task.md
中的目标、范围和验收，遵循 docs/code-review.md；独立核对相关源码与证据，
输出按影响排序的发现和未验证项，不修改被审查实现，不判断实验结论是否可采纳。
```

将这段说明作为 `codex review` 的自定义 prompt。`--uncommitted`、`--base`、`--commit` 与自定义 prompt 互斥，不能组合使用。

## 审查与修复

- 优先检查参考模型、测试、约束和指标处理，再检查实现与调用者是否符合约定。
- 发现须附影响、代码位置及证据或复现方法。未能确认的问题标为待核验；没有明确发现时如实说明，不凑问题数量。
- 输出已检查范围和未验证项，不用自报置信度代替证据。审查者不直接修改代码或放宽验收标准。
- 实现 Agent 处理发现，记录修复提交或不采纳的理由；修复后复核受影响部分。超出约定预算或反复阻塞时，说明问题并交由人决定。
- 原始运行产物或本地依赖不可用时，说明覆盖限制。不得将“未发现问题”写成“实验结论已被批准”。

官方入口说明：[Code review](https://learn.chatgpt.com/docs/code-review)、[CLI review 参数](https://learn.chatgpt.com/docs/developer-commands)。
