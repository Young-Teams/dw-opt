# 任务与人工审阅

每项需要持续跟踪的开发或实验任务使用一个子目录：

```text
tasks/<任务名>/
├── task.md       # 目标、版本、运行索引、结果和审阅记录
└── config/       # 按需建立：参数、SDC、输入清单或其他复现配置
```

任务说明和配置纳入 Git。简单修改直接在对话中约定即可，无需为每次编辑创建任务目录。

从仓库根目录创建任务，例如：

```bash
mkdir -p tasks/mul-baseline
cp docs/templates/task.md tasks/mul-baseline/task.md
```

先填写目标、范围、验收及适用的资源预算。开发与实验过程中持续更新代码版本、配置和 Run 索引；原始产物保存在 [experiments/](../experiments/README.md)。路径统一以仓库根目录为基准，便于跨任务定位。

`task.md` 承担任务说明、代码审查记录和实验报告的职责，不强制创建 PR。代码审查按[触发条件](../docs/code-review.md)执行。实验结果与结论由人审阅：Agent 可以完成运行与分析、标记“待人工审阅”，人工决定及意见由人提供，Agent 不代填通过结论。

记录实际产生结果的代码提交、配置与输入哈希。若运行输入有未提交修改，还需保留其差异或内容快照；仅记录 HEAD 不足以复现。任务报告可在之后的提交中更新，无需引用包含报告自身的提交。

结果目录不随 Git 同步。需要在另一台机器复核时，应单独提供原始 Run；结果缺失时保留对应状态，不能仅凭任务报告宣称复现成功。
